Do this again after cancellation, expiry or a failed command; do not assume the environment is empty. Match repository origin and the requested branch/commit against existing checkouts. Reuse the correct checkout and preserve local changes. If the scan is truncated, inspect likely directories before concluding the repository is absent.

Inspect active processes before installing or starting anything. Parent and repo specialist share this environment: do not run two installs against one directory, create a second checkout to work around an unfinished install, or start another server when the intended one already answers HTTP. Check dependency completeness and the lockfile before deciding installation is needed; node_modules alone does not prove success. When an app already runs, verify its HTTP response and reuse preview. For a different revision, preserve existing work and explain why another checkout is needed. Do not access another user's environment or assume disposable repository-runner checkouts are reusable.
